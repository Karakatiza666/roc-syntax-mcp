# Refreshing the basic-cli corpus

basic-cli is one of two platform upstreams. Each one has its own release
schedule, and the gates check each one with the nightly of its release.
`reference/basic-webserver.md` covers the other platform and everything that
the two share. This page covers only the differences. There are two reasons to
refresh this corpus, and each one needs different work:

| Trigger | What has to happen |
|---|---|
| A new basic-cli release | Move the `release` URL, run `npm run build:index`, regenerate the patch, set the `compiler` line to the nightly of the release, and repin every site below |
| A compiler nightly bump | Nothing here. The corpus stays on the nightly of its release. Run the gates again, and record in the commit that the platform was checked again |

Every app here pins its platform by tarball URL. Thus `check:platforms` gives
the compiler the released platform, and checks the release with its own
nightly, by the rule in `SKILL.md`.

`corpus/platforms/basic-cli/UPSTREAM` records the pinned tag, the tarball hash,
the compiler nightly, the path mapping, and what was intentionally left out.
Diff against it. Do not guess.

## What is bundled

| Path | Source | Note |
|---|---|---|
| `corpus/platforms/basic-cli/index.json` | `platform/` at the tag, parsed | Generated by `npm run build:index` from the compiler's package cache. No source is vendored |
| `corpus/platforms/basic-cli/examples/` | `examples/*.roc`, patched | See the patch below |
| `corpus/platforms/basic-cli/topics/` | Ours | Complete apps. This is the derived content with the highest risk here |
| `corpus/platforms/basic-cli/scaffold.roc` | Ours | The app that `roc_check` wraps bare code in |
| `corpus/platforms/basic-cli/verify/` | Ours | One app that holds every snippet of the overview page, so the page cannot drift |
| `corpus/platforms/basic-cli/overview.md` | Ours | Under 2000 tokens, asserted by a test |

The `roc-lang/http` package is shared with basic-webserver. It is indexed once
at `corpus/packages/http/` and listed under both scopes. Its provenance file is
`corpus/packages/http/UPSTREAM`. Change it only when both platforms pin the same
new release.

basic-cli ships no prose pages. Upstream's `docs/` holds a redirect stub, and its
`README.md` is curated into the overview, not bundled. The scope declares no
`docs` directory, and `src/scopes.test.ts` asserts that.

## The patch

The examples tree is the patched result, not a direct copy of upstream.
Regenerate it from a fresh checkout of the tag. Do not edit it in place:

```bash
patch -p1 < corpus/platforms/basic-cli/patches/0001-repin-examples-*.patch
```

`0001` is necessary, because every example at a tag pins the previous platform
release. Thus a fresh checkout never compiles against its own release. There is
no second patch, and there should not be one. Nothing in this corpus depends on
a third-party package, and a third-party package is the only reason that
basic-webserver has a second patch. Regenerate `0001` against the new tag. Do
not try to rebase the old one.

## Repinning

The release version appears in more places than a search for the tag finds,
because most of them carry the tarball hash. The version and the hash change
together.

| Site | What to change |
|---|---|
| `corpus/platforms/basic-cli/plugin.json` | `version`, and the `release` URL. Then `npm run build:index` |
| `corpus/platforms/basic-cli/scaffold.roc` | Both package URLs in the header |
| `corpus/platforms/basic-cli/topics/*.roc` | The same header. Two of them also pin `http` |
| `corpus/platforms/basic-cli/verify/*.roc` | The same header |
| `corpus/platforms/basic-cli/examples/*.roc` | Regenerated by patch `0001` |
| `corpus/platforms/basic-cli/overview.md` | The header snippet |
| `scripts/check-detection.sh`, `scripts/check-roc-check.mjs` | Fixture headers |
| `src/detect.test.ts`, `src/detect_server.test.ts` | The basic-cli URL helpers, and the version that each assertion names |
| `corpus/platforms/basic-cli/UPSTREAM` | Tag, commit, tarball hash, and the `compiler` line |

`src/upstream.test.ts` finds the most important missed sites. It asserts the tag
against `src/scopes.ts` and the tarball against the scaffold. Thus an incomplete
repin fails the suite and does not ship.

## Gates

The gates are in order, cheapest first. The last three need `ROC` exported, as
in Step 0 of `SKILL.md`. Without it, they report that they skipped, and they do
not fail.

```bash
npm run build:ts
npm test
npm run check:platforms      # every program, both platforms
npm run check:roc-check
npm run check:detection      # needs the claude CLI
node .claude/skills/refresh-roc-upstream/scripts/tool-cost.mjs
```

## Traps specific to this corpus

- basic-cli and basic-webserver declare many of the same full names, and they
  disagree about approximately half of them. `Cmd`, `Env`, `File`, `Http`,
  `IOErr`, `OsStr`, `Path`, `Sleep`, `Sqlite`, `Stderr`, `Stdout`, `Tcp` and
  `Url` are module names in both. These names never collide, because an address
  space holds at most one platform and an app pins one. The cost for a refresh
  is that a shared name has two declarations. A signature change here changes
  only what a basic-cli workspace sees. The same name in the other corpus is a
  separate decision. `src/scopes.test.ts` asserts that a space holds one
  platform. Do not "fix" a duplicate by removing one of the two.
- Much of the public API has no type annotation upstream. `Sqlite.query_many!`,
  `Sqlite.str` and every other row decoder, `Tcp.connect!` and
  `File.open_reader!` are declared as bare `name = |args|`. The parser indexes
  them with their lambda head and marks them `unannotated`. This keeps them out
  of signature search, because a lambda head is not a type. An app that calls
  one usually must annotate the result itself, or no later call can dispatch on
  it. The topics show this.
- `InternalSqlite.roc` uses four spaces for indentation, while every other
  upstream file uses tabs. The parser detects the unit for each file. If a
  future file mixes the two, the parser counts tabs and indexes nothing from the
  parts indented with spaces.
- `File` is almost empty. Everything that an app would look for under `File` is
  on `Path`. The overview says so, because the module name misleads.
- The examples refer to `examples/todos.db` and `examples/todos2.db`. These are
  binary fixtures, and they are not bundled. `roc check` never opens them, so
  the gates cannot see that they are missing. Only a user who runs an example
  would see the problem.
