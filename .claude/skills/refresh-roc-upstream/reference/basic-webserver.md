# Refreshing the basic-webserver corpus

basic-webserver is one of two platform upstreams. Each one has its own release
schedule, and both are refreshed under the same compiler nightly as the language
corpus. `reference/basic-cli.md` covers the other platform. There are two
reasons to refresh this corpus, and each one needs different work:

| Trigger | What has to happen |
|---|---|
| A new basic-webserver release | Move the `release` URL, run `npm run build:index`, regenerate the patches, and repin every site below |
| A compiler nightly bump | Regenerate patch `0003`, then run the gates again. If they pass, index nothing again and update the `compiler` line. If they fail, find a release that builds with the nightly, or keep the old nightly |

Both triggers go in the same commit as the language refresh. `SKILL.md` gives
the reason. Every app here pins its platform by tarball URL, so
`check:platforms` gives the compiler the released platform, and the gate checks
the nightly and the tag as a pair. You cannot validate one of them alone.

`corpus/platforms/basic-webserver/UPSTREAM` records the pinned tag, the tarball
hashes, the compiler nightly, the path mapping, and what was intentionally left
out. Diff against it. Do not guess.

## What is bundled

| Path | Source | Note |
|---|---|---|
| `corpus/platforms/basic-webserver/index.json` | `platform/` at the tag, parsed | Generated by `npm run build:index` from the compiler's package cache. No source is vendored |
| `corpus/packages/http/index.json` | `roc-lang/http` `package/`, parsed | Shared with basic-cli. It is indexed once and listed under both scopes, and it has no scope of its own, because neither platform works without it. Provenance in `corpus/packages/http/UPSTREAM` |
| `corpus/platforms/basic-webserver/examples/` | `examples/*.roc`, patched | See the patch series below |
| `corpus/platforms/basic-webserver/docs/` | `docs/sse.md`, `docs/benchmarking.md` | Prose, copied unchanged |
| `corpus/platforms/basic-webserver/topics/` | Ours | Complete apps. This is the derived content with the highest risk here |
| `corpus/platforms/basic-webserver/scaffold.roc` | Ours | The app that `roc_check` wraps bare code in |
| `corpus/platforms/basic-webserver/verify/` | Ours | One app that holds every snippet of the overview page, so the page cannot drift |
| `corpus/platforms/basic-webserver/overview.md` | Ours | Under 2000 tokens, asserted by a test |

## The patch series

The examples tree is the patched result, not a direct copy of upstream.
Regenerate it from a fresh checkout of the tag. Do not edit it in place:

```bash
patch -p1 < corpus/platforms/basic-webserver/patches/0001-repin-examples-*.patch
patch -p1 < corpus/platforms/basic-webserver/patches/0002-restore-parked-gregorian-examples.patch
patch -p1 < corpus/platforms/basic-webserver/patches/0003-repin-roc-nightly.patch
```

`0001` is necessary, because every example at a tag pins the previous platform
release. Thus a fresh checkout never compiles against its own release.

`0002` removes `gregorian`, which does not build under the pinned nightly.
Starting with 0.17.0, upstream parks its gregorian examples as `.todoroc` files,
so `0002` also renames them back to `.roc`. Generate `0002` from a scratch git
repo (`git diff -M`), so that it records renames and not full-file deletes and
adds.

Regenerate the patches against the new tag. Do not try to rebase the old ones.

`0003` sets the `roc: "nightly-..."` line of every example to the bundled
nightly. Upstream pins a nightly in each header, and a pin that is one day off
gives a warning. The gate counts that warning as a failure, so without `0003`
every example fails after a bump. Thus regenerate `0003` on every nightly bump,
even when nothing else changes. `0003` changes only that line, so `0002` leaves
the pin of the parked files unchanged.

Keep `0002` small. It exists because a third-party package broke. When gregorian
builds again, delete `0002`. Do not keep it.

## Repinning

The release version appears in more places than a search for the tag finds,
because most of them carry the tarball hash. The version and the hash change
together.

| Site | What to change |
|---|---|
| `corpus/platforms/basic-webserver/plugin.json` | `version`, and the `release` URL. Then `npm run build:index` |
| `corpus/platforms/basic-webserver/scaffold.roc` | Both package URLs in the header |
| `corpus/platforms/basic-webserver/topics/*.roc` | The same header |
| `corpus/platforms/basic-webserver/verify/*.roc` | The same header |
| `corpus/platforms/basic-webserver/examples/*.roc` | Regenerated by patch `0001` |
| `corpus/platforms/basic-webserver/overview.md` | The header snippet |
| `scripts/check-detection.sh`, `scripts/check-roc-check.mjs` | Fixture headers |
| `src/detect.test.ts`, `src/detect_server.test.ts` | `BUNDLED`, and the mismatch fixtures, which need a version on each side of the bundled one |
| `corpus/platforms/basic-webserver/UPSTREAM` | Tag, commit, tarball hash, and the `compiler` line |
| `corpus/language/UPSTREAM`, `corpus/platforms/basic-cli/UPSTREAM` | Their `compiler` lines, which must name the same nightly |
| `corpus/packages/http/UPSTREAM` | Only if `corpus/packages/http/` changed, which needs basic-cli to pin the same release |

Not every missed site causes a failure. Tests cover the most important sites:

- `src/scopes.test.ts` asserts the origin string.
- `src/detect.test.ts` asserts the bundled version.
- `src/upstream.test.ts` asserts the tag, and the tarball against the scaffold.

A missed site elsewhere shows as a `roc check` failure, or it does not show at
all.

## Gates

The gates are in order, cheapest first. The last three need `ROC` exported, as
in Step 0 of `SKILL.md`. Without it, they report that they skipped, and they do
not fail.

```bash
npm run build:ts
npm test
npm run check:platforms      # every program, both platforms
npm run check:roc-check
npm run check:detection      # needs the claude CLI
node .claude/skills/refresh-roc-upstream/scripts/tool-cost.mjs
```

`check:platforms` is the most important gate. It proves that the bundled apps
build with the release that they pin, not only that they were copied from a
source near it. The first run downloads approximately 50 MB and takes
approximately 30 s. Later runs take tens of milliseconds per file. It does not
check `index.json`. `check:index` asserts that each `index.json` equals its
release.

## Traps specific to this corpus

- A file-level declaration that does not have the name of its file is
  unreachable. In a platform, one file is one module, and only a declaration
  whose name equals the file basename is visible outside the module block.
  `Html.roc` declares `HtmlNode` there and aliases it as `Node` inside. An app
  can write `Html.Node` but cannot write `Html.HtmlNode`. There are two such
  cases in the platform, and the parser indexes both at tier `private`. See
  `parser-traps.md`.
- The `exposes` list sets the host-tier boundary. The parser reads the list from
  `main.roc` and does not hardcode it. Thus a module that a new release exposes
  does not stay in the host tier without notice. After a refresh, check that the
  count changed.
- `roc check` deletes every `/tmp/roc-*` directory at startup. Do not use that
  name for anything that the server or a script writes for the compiler to read.
  `src/roc_check.ts` uses `mcp-roc-*`. If `roc check` deletes such a directory,
  a file written moments before gives "file not found". This looks like a
  compiler bug, but the cause is the directory name.
- basic-cli declares many of the same names, and disagrees about the type of
  approximately half of them. `Cmd.exec!` here reports a timeout, and the
  basic-cli version cannot. `Env.dict!` returns records here and tuples in
  basic-cli. A refresh that changes a shared signature changes what
  `lookup_builtin` prints under two headings. Thus, before you assume that a
  rename is local, check whether basic-cli also has the name.
- Nothing type-checks the `index.json` files. Every gate here compiles apps,
  and every app resolves its platform from the tarball URL. Thus a hand edit in
  an index shows only as a wrong answer from `lookup_builtin`. Regenerate the
  files with `npm run build:index`. `check:index` fails on any other edit.
- A broken third-party package hides the real error. If you add `gregorian` to
  an app with one error, the compiler reports 15 errors, 14 of them in
  `Date.roc`. `roc_check` separates them. If you add a package to the scaffold,
  the scaffold gets this problem. Put nothing third-party in the scaffold.
